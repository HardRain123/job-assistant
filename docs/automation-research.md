维护证据：[候选一提交](https://github.com/mrcxsy/boss-auto-apply/commits/main/)、[候选二提交](https://github.com/h1077/BossJob-Helper/commits/main/)、[候选三提交](https://github.com/yinren112/open-boss/commits/main/)。这些仓库的成功或安全声明不能视为本项目实测证据。

结论：沿用 Fastify/SQLite 与原生 MV3，自行实现有租约的只读命令队列。扩展通过官方 [Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle) 与 alarms 恢复轮询；SQLite 保存任务进度，扩展只处理搜索/下一页/岗位详情三种固定命令。

实施顺序：

1. 后端持久化单一活动任务、一次一条命令、租约与幂等回执，边界为每批最多 50 个详情、每关键词最多 10 页、最多 5 个关键词。
2. 扩展拥有独立搜索/详情标签页，读取可见 DOM，翻页前后核对岗位列表变化。登录、验证、页面不识别或标签被关闭时暂停，不使用隐藏 API。
3. 工作台一键启动、显示采集/评分进度、暂停/恢复/停止。暂停后禁止领取新命令；已经开始的只读导航可能完成，过期回执不能推进任务。
4. 详情入库后后端依次调用现有硬条件及评分链，保留回退、阈值、缓存和失败状态。模型及个人简历不进入扩展命令。
5. 用模拟扩展跨 API 验证多页、跨关键词、去重、租约、取消及评分；随后在安装升级后的真实 BOSS 页面验收。自动发送是下一步，不能把本阶段采集完成标为投递完成。

## 新版同页详情适配（2026-09-28）

用户截图确认 `/web/geek/jobs` 页面采用左侧职位卡片、右侧职位描述的布局。补充参考 [auto-zhipin 的页面适配源码](https://github.com/ufownl/auto-zhipin/blob/main/boss_zhipin.py) 与 [BossHunter 的卡片抽取源码](https://github.com/powerycy/BossHunter/blob/main/src/bosshunter/scraper/jobs.py)：新版卡片使用 `.job-card-wrap` / `.job-card-box`，详情容器为 `.job-detail-box`。只引用 DOM 结构事实，未复制候选项目实现，也不采用其 Cookie 读写或浏览器反检测设置。

扩展优先在本次搜索标签页点击精确岗位链接对应的卡片，再读取更新后的右侧详情。后端命令绑定搜索页地址；回执区分实际页面地址与独立岗位链接，并验证关键词、城市、目标岗位、标题和公司的一致性。无法排除旧详情或重复标题歧义时停止读取。工资字体含无法确认的字符时保留未知，不猜测数值。截图能确认布局，但不能代替真实 DOM 和端到端采集验收。
