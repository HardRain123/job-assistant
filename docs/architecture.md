## 数据与动作

只有 API 服务写 SQLite。浏览器服务持有浏览器资料和只读简历附件；通过带认证的任务 API 领取租约并报告结果。每次外部动作前写日志，不能确定是否发送时进入人工核对。一个账号同时只运行一个浏览器任务。先发消息、再发简历，平台招呼、自定义话术与附件各有独立状态。

岗位按来源和来源 ID 去重，内容改变生成快照。只读采集失败不会自动把岗位认定为下架。应用端重新计算内容摘要，以防上游没有更新摘要造成评分缓存错误。向量缓存键包含向量服务、模型、维度及岗位内容。

## 匹配

地点、月薪下限、公司/行业排除和必要技能先做通过/不通过/未知判断。任意不通过不能被模型高分覆盖；未知、临界分数进入复核。语义相似度与应聘适合程度分开展示。模型回退不会降低用户阈值。模型结果必须结构有效、分值有范围且包含证据；全部模型失败时显示不可评估。

## 模型与授权

兼容 API 使用明确协议适配器，禁止把任意响应当成成功。ChatGPT 使用专用 Codex App Server 进程和账号卷，固定 CLI 版本，不读取宿主机账号。桥接仅监听回环地址，与 app 共享容器网络命名空间；每个业务请求仍校验内部令牌。模型评分不向外暴露任意工具或执行接口。

相关官方文档：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[认证](https://learn.chatgpt.com/docs/auth)、[Playwright Docker](https://playwright.dev/docs/docker)。协议存在不等于实际账号已验收；版本升级需要重跑协议和隔离测试。

## 后续验收条件

当前重点是建立可复核的本地流程。Docker 冷启动、真实 ChatGPT 登录、BOSS 页面身份核对和消息/附件回执，必须在对应环境实测后才能标记通过。此之前不会声称完成真实投递。通用官网自动填表、反验证码、自动回复 HR、云端多租户不在首版范围内。
