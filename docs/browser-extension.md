## 实施顺序与边界

1. Docker 工作台登录后签发五分钟、一次性配对码；扩展换取七天有效的独立令牌，服务端只保存摘要。新配对替换旧连接，工作台可随时撤销。
2. 原生 Chrome/Edge MV3 扩展从本机工作台领取有限的搜索、翻页和详情读取命令，只在 www.zhipin.com 操作专用标签页及读取已渲染岗位信息；不读取 Cookie、私有接口或聊天正文。弹窗手动预览导入作为补充入口。
3. 后端统一校验岗位链接、归一化月薪、去重和保存快照，沿用已有检索与评分。
4. 工作台“自动找岗位”按关键词、城市、采集上限和每个关键词的翻页上限编排任务。详情入库后可自动评分；配置变化、重复页面、登录失效和验证页面会停止任务。安装后仍需在用户真实页面核验选择器，无法识别时明确失败，不用虚构职位填充。
5. 单岗位和批量发送均核对会话身份及新消息回执；批量目前只发话术。0.4.8 已完成连续两个新岗位的自动发送，连续十个岗位及自动补采闭环仍需真实验收，详见 [验证状态](verification.md)。

扩展不使用 debugger、远程调试端口、Cookie 权限或隐藏接口。不改变 BOSS 的安全脚本。扩展主机权限只限 BOSS 和本机地址；Chrome 主机权限不按端口细分，因此代码额外固定后端为 `http://127.0.0.1:3000`。

## 安装与使用

1. 保持 Docker 工作台运行。在常用 Chrome 打开 `chrome://extensions`，或 Edge 打开 `edge://extensions`。
2. 打开“开发者模式”，选择“加载已解压的扩展程序”，选择项目的 `apps/browser-extension` 文件夹（含 manifest.json），固定扩展图标。
3. 登录本地工作台，进入“浏览器”页的“普通浏览器连接”，生成配对码。在扩展弹窗粘贴并连接。
4. 用该浏览器正常登录 BOSS。返回工作台“自动找岗位”，输入关键词并设置城市、采集数量和每个关键词的最多页数；默认采集 10 个并在完成后自动评分。
5. 点击开始后，扩展自动创建搜索与详情标签页，依次读取并入库；保持浏览器运行，不要手动切换专用标签页的地址。关闭扩展弹窗不会停止任务；空闲时最多约 30 秒领取一次任务。
6. 在任务面板查看进度，按需暂停、恢复或取消；在“岗位库”查看内容和评分。描述不全或公司行业未知的岗位仍按现有规则待核对。投递队列的暂停状态不控制本页采集任务。

### 从 0.1.0 升级

项目文件更新后，在 Chrome/Edge 扩展管理页点击本扩展的刷新图标，确认版本为 **0.4.13**；无需删除扩展。已有有效配对保留，工作台会显示最近上报的版本。若尚未配对，在浏览器工具栏的扩展弹窗中粘贴工作台生成的配对码，不是在扩展详情页粘贴。所有扩展状态查询使用 POST，校验精确来源与配对凭证。

0.4.13 在滚动时激活本任务的搜索标签页，降低后台页面延迟加载的影响；底部确认按实际时间至少稳定两秒，并保留多次采样、次数和总等待上限。达到等待、滚动次数、控件读取上限或页面未移动时分别显示原因，不当作已经到达列表结尾。

0.4.12 根据真实诊断补充“中文姓名／公司／招聘助理”格式，其他收件人核对保持不变。列表没有翻页入口但仍可滚动时，先对唯一岗位列表对应的容器进行有限滚动，读取新增岗位或底部翻页入口；确认到底无新增后结束续载，达到等待或步数上限则明确报错。每次读取最多保留 300 个链接，后端按岗位链接去重；配置中的轮数、页数和采集总量仍限制任务。真实效果须加载新版后验证。

0.4.11 增加两项只读诊断，用于定位真实批次中的识别问题，尚不改变招聘者准入或列表续载动作。待核验的扩展投递记录可展开“检查聊天页识别问题”：空闲时检查已打开、岗位与公司及地点薪资均匹配的聊天页，仅返回顶部有限的姓名与职务候选，不读取聊天消息、不打开会话或发送内容，也不更改投递结果。诊断需单独发起，五分钟过期，不自动重试。自动采集同时记录翻页控件计数和滚动容器尺寸，可在采集任务中查看，不保存网页原文；这些数据不作为岗位事实或投递授权。

0.4.10 修复同一岗位的卡片与详情地点粒度不同被清空的问题：仅当城市、区县与商圈是完整前缀关系时保留较详细地址，跨城、区县或商圈冲突仍保持未知。不使用搜索城市代填岗位地址。该修复须刷新扩展加载，已有未知记录须重新采集和评分。

0.4.9 在搜索和翻页结果上报前，同时核对标签页与页面文档的关键词及城市，防止其他搜索页面被计入本次采集。后端的自动补采、评分与批量发送兼容 0.4.8，无需为后端更新反复刷新扩展。在“批量投递 → 自动补充并投递”预览关键词、目标、轮数和话术后启动；该工作流统一控制子任务的暂停、继续与结束。单岗位异常可隔离，未知动作保持待核验且不重发；连续三次异常和账号级阻断暂停整个批次。

连续失败计数由后端保存，跨补采轮次、子批次及重启累计；完整成功或用户显式继续才清零。旧批次先从持久化记录恢复，证据不足时暂停核对。此项后端修复不需要重新配对或刷新扩展。

0.4.8 在每段发送前等待同一聊天页面在前台稳定五秒，检查离线、加载、草稿及可见连接或发送限制提示。回执最多等待三十秒，但不点击重发；临时气泡刷新后消失不算成功。未知发送保留待核对，不自动补发。此版本针对实测失败补充等待与诊断，仍需在真实页面验证，不能把等待结束等同于连接成功。

0.4.0 增加普通浏览器批量话术发送：工作台预览并确认后串行执行，每个岗位分别记录沟通和消息回执。已沟通岗位跳过，成功任务关闭专用标签页，未知结果保留页面并暂停批次。批量不发送附件或图片；默认每日目标 150 并非平台统一额度声明。每日占额按上海日期记录，未知操作不会释放名额；在 BOSS 手动发起的沟通不在本地统计范围内，平台提示限额时停止。

0.4.1 保存详情页的关闭状态并在发送前再次检查。品牌没有公司链接时，仅在同页可见工商信息确认法人全称且公司信息卡唯一、完整时提取品牌及行业；冲突继续保留未知。批量发送要求 0.4.2 或更新版本。

0.4.2 补充新沟通后仍停留在详情页的继续入口；再次核对同一岗位后打开会话，不重发招呼。本批未知沟通经只读检查接续后，可继续未执行的话术；普通历史联系人仍跳过。

0.4.3 聊天顶部的薪资核对支持 `23-29K·13薪` 等带薪数格式；月薪区间或已知薪数有差异时仍停止。

0.4.4 消息回执识别兼容嵌套正文、消息内容节点及同一气泡内独立的送达标记。必须同时确认本人身份、发送后新增的完整正文和成功回执；历史消息重绘、输入框清空或点击发送本身都不算成功。失败时，投递记录显示受限计数诊断，不保存聊天内容。人工核对第一段后可将剩余动作重新排队；批次仍保持暂停，须在批量投递页继续后才会执行。

如果暂停期间修改了话术，单岗位纯文本批次可在“核对已发送的消息”中选择“预览最新话术后接续”，阅读新版后再确认。只替换未发送段落；简历、策略、已尝试正文等发生变化时仍拒绝接续。此功能仅更新后端和工作台，扩展保持 0.4.4。

0.4.5 为缺少已知正文样式的消息增加整段精确匹配：必须是完整话术与单独可见的成功状态组合，仍拒绝引用、额外文字、失败标记及对方消息。最后一段结果未知时，经人工核对及同岗位只读复查，可完成记录而不重新排队；已无剩余任务及待核对项的暂停批次同步结束。人工确认保留原始未知回执，不视为自动识别成功。

发送前异常导致所有动作仍未执行时，可使用“重试尚未发送的任务”；暂停批次仍须主动继续。若期间修改了筛选条件或话术，应结束旧批次并重新评估和预览。结束批次只释放从未执行、没有证据和占额的失败草稿，原任务和冻结内容保留审计；已尝试或未知的发送继续阻止重复投递。

0.4.6 支持聊天头部“中文姓名／公司／HR”格式。无称谓的姓名必须与唯一、匹配的公司及明确招聘角色处于同一行且顺序对应，仍拒绝在线状态、隐藏内容、歧义姓名和公司冲突。会话绑定保留完整头部标记，切换招聘者后停止发送。

0.4.7 兼容聊天岗位栏省略区县和商圈：例如冻结地点“上海·浦东新区·张江”可对应“上海”或“上海·浦东新区”。仅对明确分段的地点接受完整前缀；不同城市、已显示的冲突区县、缺失地点或多个匹配字段仍拒绝。该规则只用于同一岗位导航后的会话核对，不改变岗位库的完整地址或城市筛选策略。

### 单岗位投递验证（0.3.0）

工作台支持对单条结果未知的文字消息进行人工核对接续：在投递记录中核对完整冻结话术确已出现在目标 BOSS 会话的发出消息中，再选择“已在 BOSS 核对，继续后续步骤”。工作台重新只读核对同一岗位、已有联系及冻结配置，记录 `user-confirmed-sent`，保留原 `unknown/send-unconfirmed` 及审计记录。领取任务时不下发这条已核对消息，只继续待执行的步骤；兼容已安装的 0.3.7，无需刷新扩展。该入口不用于附件或尚未核实的消息，不等于程序已取得自动发送回执；当前仅支持原生招呼已经通过既有沟通核对的任务。

0.3.7 修复带子元素的“查看职位”入口被过滤的问题：保留最内层的同文案节点，不再要求没有子元素；多个独立入口仍拒绝识别。岗位字段、公司、招聘人和会话绑定要求保持不变。

0.3.6 为页面脚本调用设置 15 秒等待上限，并在任务超过两分钟时停止继续执行步骤；失效的调用授权被撤销。已存在会话的导航无返回时可只读核对目标聊天页，不再点击；任何已开始的发送超时仍记为未知，禁止自动重发。

0.3.5 为无链接聊天头部增加逐层诊断：区分来源、区域边界、查看职位入口、岗位与城市、薪资、雇主、招聘人称呼及会话绑定失败。诊断仅包含固定代码与上限计数，最多 12 层；工作台可展开查看，不保存头部原文、聊天原文或 HTML。诊断不会改变发送授权或收件人判断。

0.3.3 增加只读核对后的受限接续：同一岗位的新近核对记录必须明确显示“继续沟通”，且岗位业务字段、话术、附件和策略不变。原生招呼保持 unknown，另记已有沟通；只导航到已存在的会话，不重发该招呼。消息或附件的未知结果不能使用此接续。会话识别失败仅返回受限计数，不读取聊天原文；完整真实发送仍待验收。

0.3.4 支持没有岗位链接的聊天顶部：仅在指定岗位发起导航后，核对岗位、城市、薪资、公司和明确的招聘人称呼，绑定当前可见头部。后续识别和发送前均核对绑定，出现冲突岗位链接或更换联系人时停止；其他称呼布局暂不支持。原生招呼已标记为已有沟通、后续全部未执行且仅页面识别失败的任务，可在重新只读核对后接续；必须保持岗位版本与配置不变，并保留原任务回执。

0.3.2 修复新标签页已开始导航、但地址尚未提交时的提前拒绝；只在地址和页面均加载完成后读取。已知错误待提交地址或错误岗位地址仍被拒绝。

0.3.1 增加不同沟通入口元素的适配；识别失败只返回入口计数和元素类型，不返回原始 HTML 或聊天内容。所有动作尚未执行且配置不变的页面识别失败任务可通过投递记录重试，保留原始失败回执。已经开始或结果未知的发送不能使用该入口重试。

在“岗位库”选择一个已评分岗位，点击“普通浏览器单岗位验证”，检查岗位、话术和附件安排后确认启动。硬条件缺失或未通过不能人工放行；复核区间中达到自动阈值的岗位可以单独确认，不改变全局策略。

任务自动打开专用标签页，核对岗位链接、标题、雇主、正文和月薪，再核对当前会话头部的雇主及岗位卡片链接。历史消息中的岗位链接不作为收件人证据。已有联系跳过平台原生招呼，新联系需要明确的平台回执。配置、岗位或附件字节改变、暂停及租约失效都会阻断发送前授权。扩展不把工作台凭据传入网页。

每段话术需要新发出的相同文本及发送状态才算确认；输入框清空不算成功。附件使用冻结的本地字节，等待对方同意与附件送达分别记录。当前实现只支持能够核对身份和回执的页面布局，不按文件名猜选平台已有简历；未识别布局和未知结果会停止，不能自动重放。该版本仍待完整真实账号验收。

0.2.15 在独立详情诊断中增加受限的公开字段证据：最多 20 行岗位头部、3 个公司区域（每区最多 16 行）及每区 8 个 BOSS 公司链接，每段最多 160 字。链接只保留公司路径，移除查询和片段。不读取原始 HTML、隐藏状态或聊天内容。证据仅保存于本地当前采集任务，最多 50 条，展示在“字段读取情况 → 页面字段证据”，不参与匹配，也不自动补写行业。需要先部署后端再刷新扩展。

0.2.14 保留同一链接及标题下已读取的工作地点；公司信息区的展示名只有与可见 BOSS 公司链接对应且唯一时才作为别名，随工商全称一起保存并用于行业区域对应。隐藏、外站链接、匿名客户不会启用此回退；先部署后端再刷新扩展。

0.2.13 根据实测诊断修复公司名称差异拦住已读取薪资的问题：独立详情的岗位链接、标题和正文已确认时，采用该页的完整记录，不把不同公司名称的两份字段拼接。公司基本信息标题支持普通元素，并在小范围祖先中寻找完整区域；匿名客户和未知行业仍需核对。

0.2.12 增加任务内的“字段读取情况”：记录读取页面、补读结果的合并情况、薪资含不可解析字符或未识别、公司信息区无法对应等固定原因。先更新 Docker 后端，再刷新扩展。诊断只包含固定状态及已核验岗位链接，不包含网页原文、凭据或任意错误文本；诊断不会改变评分与投递条件。

0.2.11 在右侧详情有完整正文但缺薪资、地点或行业时，对绑定的岗位链接增加一次独立详情读取；标题和公司可核对才补充字段，冲突值仍保留未知。独立页无法读取时保存已经核实的同页岗位，登录或人工验证依然阻断任务。真实字段补齐效果需要刷新扩展后重新采集确认。

0.2.10 为独立详情增加有限的可见文字回退：薪资和地点只从同一职位头部读取；公司基本信息区只有名称一致且字段边界明确时才补充行业。字段冲突、匿名雇主、中介归属不明或乱码薪资继续保持未知，不从推荐岗位或整页关键词推断。本地合成测试已通过，真实网页补齐效果仍待刷新后的采集验收。

0.2.8 修复同页详情遗漏行业、乱码薪资遮蔽同一卡片可读薪资、隐藏的首个节点遮蔽后续有效字段，以及公司名称混入字段标签的问题。薪资无法可靠读取时仍为空；“面议”不会被猜成数字。分栏行业只取当前岗位区域的显式行业字段；匿名客户、猎头、中介归属不明确或两处行业冲突时保留未知。本版本不增加浏览器权限，也不开放消息或简历发送；实际字段补齐效果需更新后重新采集验证。

0.2.9 对“点击后详情未更新”增加一次独立详情页读取：仅打开命令绑定的公开岗位链接，重新检查登录、验证、完整正文及岗位 URL。分栏身份不符、搜索页改变、未知错误不会触发该重试；独立页仍失败时交回原有失败处理，不循环打开页面。

0.2.4 增加新版左右分栏页面适配：在当前搜索页点击目标卡片，核对右侧详情与该卡片身份后入库。后台回执保存独立岗位链接，实际页面地址单独校验；身份不明确或疑似旧详情时停止。失败原因不会再被空闲轮询覆盖。字体混淆等原因导致薪资数字不可确认时按未知处理，进入待复核，不能视为已满足最低月薪。
