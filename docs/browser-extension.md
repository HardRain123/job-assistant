## 实施顺序与边界

1. Docker 工作台登录后签发五分钟、一次性配对码；扩展换取七天有效的独立令牌，服务端只保存摘要。新配对替换旧连接，工作台可随时撤销。
2. 原生 Chrome/Edge MV3 扩展从本机工作台领取有限的搜索、翻页和详情读取命令，只在 www.zhipin.com 操作专用标签页及读取已渲染岗位信息；不读取 Cookie、私有接口或聊天正文。弹窗手动预览导入作为补充入口。
3. 后端统一校验岗位链接、归一化月薪、去重和保存快照，沿用已有检索与评分。
4. 工作台“自动找岗位”按关键词、城市、采集上限和每个关键词的翻页上限编排任务。详情入库后可自动评分；配置变化、重复页面、登录失效和验证页面会停止任务。安装后仍需在用户真实页面核验选择器，无法识别时明确失败，不用虚构职位填充。
5. 0.3.0 新增明确确认后的单岗位发送实验入口。只有核对会话身份、观察到新消息和附件回执才确认完成；连接成功不代表可投递。完整真实发送仍待验收，批量发送未开放。

扩展不使用 debugger、远程调试端口、Cookie 权限或隐藏接口。不改变 BOSS 的安全脚本。扩展主机权限只限 BOSS 和本机地址；Chrome 主机权限不按端口细分，因此代码额外固定后端为 `http://127.0.0.1:3000`。

## 安装与使用

1. 保持 Docker 工作台运行。在常用 Chrome 打开 `chrome://extensions`，或 Edge 打开 `edge://extensions`。
2. 打开“开发者模式”，选择“加载已解压的扩展程序”，选择项目的 `apps/browser-extension` 文件夹（含 manifest.json），固定扩展图标。
3. 登录本地工作台，进入“浏览器”页的“普通浏览器连接”，生成配对码。在扩展弹窗粘贴并连接。
4. 用该浏览器正常登录 BOSS。返回工作台“自动找岗位”，输入关键词并设置城市、采集数量和每个关键词的最多页数；默认采集 10 个并在完成后自动评分。
5. 点击开始后，扩展自动创建搜索与详情标签页，依次读取并入库；保持浏览器运行，不要手动切换专用标签页的地址。关闭扩展弹窗不会停止任务；空闲时最多约 30 秒领取一次任务。
6. 在任务面板查看进度，按需暂停、恢复或取消；在“岗位库”查看内容和评分。描述不全或公司行业未知的岗位仍按现有规则待核对。投递队列的暂停状态不控制本页采集任务。

### 从 0.1.0 升级

项目文件更新后，在 Chrome/Edge 扩展管理页点击本扩展的刷新图标，确认版本为 **0.3.3**；无需删除扩展。已有有效配对保留，工作台会显示最近上报的版本。若尚未配对，在浏览器工具栏的扩展弹窗中粘贴工作台生成的配对码，不是在扩展详情页粘贴。所有扩展状态查询使用 POST，校验精确来源与配对凭证。

### 单岗位投递验证（0.3.0）

0.3.3 增加只读核对后的受限接续：同一岗位的新近核对记录必须明确显示“继续沟通”，且岗位业务字段、话术、附件和策略不变。原生招呼保持 unknown，另记已有沟通；只导航到已存在的会话，不重发该招呼。消息或附件的未知结果不能使用此接续。会话识别失败仅返回受限计数，不读取聊天原文；完整真实发送仍待验收。

0.3.2 修复新标签页已开始导航、但地址尚未提交时的提前拒绝；只在地址和页面均加载完成后读取。已知错误待提交地址或错误岗位地址仍被拒绝。

0.3.1 增加不同沟通入口元素的适配；识别失败只返回入口计数和元素类型，不返回原始 HTML 或聊天内容。所有动作尚未执行且配置不变的页面识别失败任务可通过投递记录重试，保留原始失败回执。已经开始或结果未知的发送不能使用该入口重试。

在“岗位库”选择一个已评分岗位，点击“普通浏览器单岗位验证”，检查岗位、话术和附件安排后确认启动。硬条件缺失或未通过不能人工放行；复核区间中达到自动阈值的岗位可以单独确认，不改变全局策略。

任务自动打开专用标签页，核对岗位链接、标题、雇主、正文和月薪，再核对当前会话头部的雇主及岗位卡片链接。历史消息中的岗位链接不作为收件人证据。已有联系跳过平台原生招呼，新联系需要明确的平台回执。配置、岗位或附件字节改变、暂停及租约失效都会阻断发送前授权。扩展不把工作台凭据传入网页。

每段话术需要新发出的相同文本及发送状态才算确认；输入框清空不算成功。附件使用冻结的本地字节，等待对方同意与附件送达分别记录。当前实现只支持能够核对身份和回执的页面布局，不按文件名猜选平台已有简历；未识别布局和未知结果会停止，不能自动重放。该版本仍待完整真实账号验收。

0.2.15 在独立详情诊断中增加受限的公开字段证据：最多 20 行岗位头部、3 个公司区域（每区最多 16 行）及每区 8 个 BOSS 公司链接，每段最多 160 字。链接只保留公司路径，移除查询和片段。不读取原始 HTML、隐藏状态或聊天内容。证据仅保存于本地当前采集任务，最多 50 条，展示在“字段读取情况 → 页面字段证据”，不参与匹配，也不自动补写行业。需要先部署后端再刷新扩展。

0.2.14 保留同一链接及标题下已读取的工作地点；公司信息区的展示名只有与可见 BOSS 公司链接对应且唯一时才作为别名，随工商全称一起保存并用于行业区域对应。隐藏、外站链接、匿名客户不会启用此回退；先部署后端再刷新扩展。

0.2.13 根据实测诊断修复公司名称差异拦住已读取薪资的问题：独立详情的岗位链接、标题和正文已确认时，采用该页的完整记录，不把不同公司名称的两份字段拼接。公司基本信息标题支持普通元素，并在小范围祖先中寻找完整区域；匿名客户和未知行业仍需核对。

0.2.12 增加任务内的“字段读取情况”：记录读取页面、补读结果的合并情况、薪资含不可解析字符或未识别、公司信息区无法对应等固定原因。先更新 Docker 后端，再刷新扩展。诊断只包含固定状态及已核验岗位链接，不包含网页原文、凭据或任意错误文本；诊断不会改变评分与投递条件。

0.2.11 在右侧详情有完整正文但缺薪资、地点或行业时，对绑定的岗位链接增加一次独立详情读取；标题和公司可核对才补充字段，冲突值仍保留未知。独立页无法读取时保存已经核实的同页岗位，登录或人工验证依然阻断任务。真实字段补齐效果需要刷新扩展后重新采集确认。

0.2.10 为独立详情增加有限的可见文字回退：薪资和地点只从同一职位头部读取；公司基本信息区只有名称一致且字段边界明确时才补充行业。字段冲突、匿名雇主、中介归属不明或乱码薪资继续保持未知，不从推荐岗位或整页关键词推断。本地合成测试已通过，真实网页补齐效果仍待刷新后的采集验收。

0.2.8 修复同页详情遗漏行业、乱码薪资遮蔽同一卡片可读薪资、隐藏的首个节点遮蔽后续有效字段，以及公司名称混入字段标签的问题。薪资无法可靠读取时仍为空；“面议”不会被猜成数字。分栏行业只取当前岗位区域的显式行业字段；匿名客户、猎头、中介归属不明确或两处行业冲突时保留未知。本版本不增加浏览器权限，也不开放消息或简历发送；实际字段补齐效果需更新后重新采集验证。

0.2.9 对“点击后详情未更新”增加一次独立详情页读取：仅打开命令绑定的公开岗位链接，重新检查登录、验证、完整正文及岗位 URL。分栏身份不符、搜索页改变、未知错误不会触发该重试；独立页仍失败时交回原有失败处理，不循环打开页面。

0.2.4 增加新版左右分栏页面适配：在当前搜索页点击目标卡片，核对右侧详情与该卡片身份后入库。后台回执保存独立岗位链接，实际页面地址单独校验；身份不明确或疑似旧详情时停止。失败原因不会再被空闲轮询覆盖。字体混淆等原因导致薪资数字不可确认时按未知处理，进入待复核，不能视为已满足最低月薪。

0.2.5 增加失败回执的执行阶段和固定错误分类，在工作台直接显示权限、脚本、地址变化、加载或识别问题。诊断不包含原始异常、网页正文或凭据。等待页面期间发生的脚本异常不再静默丢失；真实页面采集仍需验收。

自动搜索功能的开源对比见 [自动采集调研](automation-research.md)，单岗位投递的方案见 [发送适配调研](application-research.md)。采集数和匹配数均不代表投递数。

扩展卸载会移除本地令牌；工作台“撤销连接”会立即撤销服务端令牌及待用配对码。后端重启会使待用配对码失效，已配对连接持久化至有效期。配对码和令牌不应写入日志、截图或版本库。
